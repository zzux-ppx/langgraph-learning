# 03 - 节点、边与循环

> 配套代码：`code/03_conditional_edges_loop.py`

## 1. add_node 的 N 种姿势

```python
builder.add_node("name", fn)                  # 最常见
builder.add_node(fn)                          # 函数名即节点名（用 __name__）
builder.add_node("agent", compiled_graph)     # 子图当节点（笔记06）
builder.add_node("tools", ToolNode(tools))    # 官方预置工具节点
builder.add_node("a", fn, retry=RetryPolicy(max_attempts=3))  # 重试策略
builder.add_node("a", fn, defer=True)         # 延迟执行（同一超步末尾才跑）
```

注意：`add_node` 只是**注册**，执行时机由边决定；注册顺序不影响执行顺序。

## 2. 三种边

### 2.1 静态边：A 完必定去 B

```python
builder.add_edge("a", "b")
builder.add_edge(START, "a")
builder.add_edge("b", END)
```

一个节点可以有多条出边（静态）——**并行分支**：`add_edge("a","b"); add_edge("a","c")`，
a 完成后 b、c 在同一个超步并行执行。

### 2.2 条件边：运行时决定去哪

```python
def route(state: State) -> str:          # 返回"下一个节点名"或 Send 列表
    if state["ok"]:
        return "end_node"
    return "retry"

builder.add_conditional_edges(
    "a",                 # 从哪个节点出发
    route,               # 路由函数（接收 state）
    {                    # 可选：把返回值映射成节点名（也是文档化）
        "end_node": "end_node",
        "retry": "retry",
    },
)
```

- 路由函数返回 `END`（即 `langgraph.graph.END`）可以直接结束；
- 返回**列表** `["b", "c"]` 表示同时去多个节点；
- 路由函数也可以是 async，且能接收 `config` 参数。

### 2.3 入口也可以是条件边

```python
builder.add_conditional_edges(START, route_fn)
```

常用于"第一个 token 之前就要分流"的场景（比如按语言分发）。

## 3. 循环：Agent 的本质

ReAct Agent 的骨架就是一个"LLM节点 → 要用工具? → 工具 → 回到LLM"的循环：

```
START ─▶ llm ─┬─(有tool_calls)─▶ tools ─▶ llm ...
              └─(没有)───────────────▶ END
```

```python
def should_continue(state):
    last = state["messages"][-1]
    return "tools" if last.tool_calls else END

builder.add_conditional_edges("llm", should_continue)
builder.add_edge("tools", "llm")
```

## 4. recursion_limit：防止死循环

LangGraph 里的"recursion"**不是函数递归**，而是**超步（superstep）计数**：
每执行一个超步（一批节点），计数 +1，超过 `recursion_limit`（默认 25）抛
`GraphRecursionError`。

```python
graph.invoke(inputs, {"recursion_limit": 50})
# 或流式时：
graph.stream(inputs, {"recursion_limit": 50}, stream_mode="values")
```

**排错技巧**：捕获 `GraphRecursionError` 后查看最后状态，确认卡在哪个环节：

```python
from langgraph.errors import GraphRecursionError
try:
    graph.invoke(inputs, config)
except GraphRecursionError:
    print(graph.get_state(config).values)   # 看卡在哪
```

## 5. 拓扑约束速查

| 规则 | 说明 |
|------|------|
| 节点必须有入边或出边 | 编译时校验，孤儿节点报错 |
| 无入边的节点只有作为 START 目标才可达 | `add_edge(START, "a")` |
| 条件边路由到不存在的节点 | 编译时不一定报错，运行时报错（配合 path_map 可静态检查） |
| 死循环 | 靠 recursion_limit 兜底 |
| 一个节点既有静态出边又有条件出边 | 静态边 + 条件边结果**合并**（都会执行），慎用 |

## 6. 设计模式建议

1. **路由函数只做"选择"，不做"计算"**：重逻辑放节点里，路由函数越薄越好测。
2. **循环一定要有明确退出条件**，且退出条件用到的字段要有 reducer 累积（如轮次计数）。
3. **节粒度**：一个节点 = 一次有意义的"状态转换"。太细（一行代码）浪费超步，太粗失去重试/打断粒度。
4. 想让循环里"每 N 轮做一次检查"，用 `Annotated[int, operator.add]` 的计数器字段 + 条件边 `state["n"] % 3 == 0`。
