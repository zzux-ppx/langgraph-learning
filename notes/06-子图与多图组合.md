# 06 - 子图与多图组合

> 配套代码：`code/06_subgraph.py`

复杂系统拆成小图，是控制复杂度的关键手段：
一个"研究 Agent"本身是带工具循环的图，把它作为一个节点装进"总控图"，
就得到多 Agent 系统（笔记 11 的基础）。

## 1. 两种嵌入方式

### 方式 A：共享 State（最简单）

父 State 与子 State 的 key 有交集，子图直接用交集部分：

```python
# 子图：一个完整的 mini agent
child = StateGraph(ChildState)...
child_graph = child.compile()

# 父图
class ParentState(TypedDict):
    messages: Annotated[list, add_messages]   # 与 ChildState 同名字段
    report: str

builder.add_node("agent", child_graph)        # 编译后的图直接当节点
```

父图流转到该节点时：**取父 State 中与子 State schema 匹配的字段**喂给子图，
子图跑到 END 后，**把子 State 中与父 schema 匹配的字段**写回父 State。
（注意：是"双向求交集"，不是整个 state 传递。）

### 方式 B：包装函数做状态映射（状态不对齐时）

```python
def call_child(state: ParentState) -> dict:
    child_out = child_graph.invoke({"question": state["raw_input"]})
    return {"messages": [AIMessage(child_out["answer"])]}

builder.add_node("agent", call_child)
```

包装函数让你完全控制进/出的字段映射，**生产中更推荐**——
显式契约，父子图解耦，各自演化不炸对方。

## 2. 什么时候用子图

| 场景 | 用法 |
|------|------|
| 复用（同一 agent 被多处调用） | 编译后的图当节点 |
| 团队分工（不同人维护不同模块） | 各自独立图 + 包装函数拼装 |
| 多 Agent 系统 | 每个 agent 一个子图，父图做 supervisor 路由 |
| 需要独立重试/打断粒度 | 子图有自己的节点边界 |

**不需要子图的场景**：简单的三五个节点线性流程，直接一张图，别过度设计。

## 3. 子图与持久化（重要）

- 子图**不需要自己的 checkpointer**：父图有 checkpointer 时，子图执行轨迹
  会自动记录在父图的 checkpoint 里（state 中以 `__pregel_node` 命名空间存档）。
- 给子图也传 checkpointer 时要小心：**子图无法独立恢复父图的线程上下文**，
  官方不建议两者都配置（除非子图要单独以独立线程运行）。
- `stream_mode="debug"` 可以看到子图内部的超步事件。

## 4. 子图里的 interrupt（重要）

子图节点里调用 `interrupt()`（笔记 09）完全合法：
中断会把整个执行栈（父图当前节点=子图，子图当前节点=interrupt 节点）存进 checkpoint，
`Command(resume=...)` 后从子图内部精确恢复。这是"审批埋在深层子图"的官方姿势。

## 5. Command 从子图跳父图

```python
def child_node(state: ChildState) -> Command:
    return Command(goto="parent_node_name", update={...})
```

要求父子共享状态（方式 A）。这是实现 **handoff（Agent 交接棒）** 的底层机制：
子 agent 干完活直接 `goto` 父图里的下一个 agent，不用回 supervisor 绕一圈。

## 6. 查看结构

print(graph.get_graph().draw_ascii())    # ASCII 图（需 pip install grandalf? 本地渲染可不用）

## 7. 常见坑

1. **父子 State 没有交集字段**：共享方式下子图收到空 state，静默跑完返回空——务必核对字段名。
2. **子图修改了父图不知道的字段**：写回时被父 schema 过滤掉，看起来"改了没生效"。
3. **只读子图也会回写共享字段（实验验证的深坑）**：共享 state 的子图完成时，
   会把它 schema 里**全部**共享字段的最终值（包括只是读过、没改过的）经父图 reducer 再应用一次。
   `messages` 用 `add_messages`（按 id 幂等）没事；但 `operator.add` 这类不幂等 reducer 会被翻倍！
   （复现：reader 子图写 notes=[x]，writer 子图只读 notes，最终 notes=[x,x]）
   解法：只读的子图用**包装函数方式**（方式B），或给 reducer 加去重幂等。
4. **在包装函数里同步 invoke 子图丢失流式细节**：想透传子图 token 流，用共享状态方式嵌入
   （框架原生子图节点才支持 `subgraphs=True` 的细粒度流，笔记 10）。
5. 子图里 `recursion_limit` 与父图**共享同一个计数器**，深嵌套时注意余量。
