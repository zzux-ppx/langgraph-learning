# 01 - 核心概念与快速上手

> 配套代码：`code/01_basic_graph.py`

## 1. 为什么需要 LangGraph

用裸写 while 循环的方式搭 LLM 应用，很快会遇到四个问题：

| 问题 | LangGraph 的答案 |
|------|------------------|
| 流程一复杂（循环、分支、并行）代码变成面条 | 把应用建模为**有向图**：节点=步骤，边=流转 |
| 状态到处传、到处改，无法追溯 | 全局 **State** + 显式 **Reducer** 合并策略 |
| 中途失败/需要人工确认，只能从头再来 | **Checkpoint 持久化**，可暂停/恢复/时间旅行 |
| 多 Agent 协作没有统一的控制流 | 图天然支持**编排（Supervisor）与循环调用** |

一句话定义：**LangGraph 是一个用于构建有状态、多角色 LLM 应用的低级编排框架和运行时。**

核心设计哲学：**不发明新概念，只用"图"这一个模型表达一切**——
RAG 是图、ReAct Agent 是带循环的图、多 Agent 系统是图套图。

## 2. 五个核心抽象

```
StateGraph   图的构建器（builder），compile() 后得到可运行的图
State        所有节点共享读写的数据结构（通常是 TypedDict/Pydantic）
Node         一个普通函数：接收 state，返回"状态更新"（partial dict）
Edge         流转规则：静态边 / 条件边 / Send 动态边
START / END  特殊节点：图的入口和出口
```

它们的关系：

```
builder = StateGraph(StateSchema)      # 1. 声明状态结构
builder.add_node("a", fn_a)            # 2. 注册节点
builder.add_edge(START, "a")           # 3. 接线
builder.add_edge("a", END)
graph = builder.compile()              # 4. 编译成 Pregel 运行时
result = graph.invoke({"k": "v"})      # 5. 运行
```

## 3. 第一个图（10 行）

```python
from typing import TypedDict
from langgraph.graph import StateGraph, START, END

class State(TypedDict):
    text: str

def step_a(state: State) -> dict:
    return {"text": state["text"] + " -> A"}

def step_b(state: State) -> dict:
    return {"text": state["text"] + " -> B"}

builder = StateGraph(State)
builder.add_node("a", step_a)
builder.add_node("b", step_b)
builder.add_edge(START, "a")   # 入口 -> a
builder.add_edge("a", "b")     # a -> b
builder.add_edge("b", END)     # b -> 出口
graph = builder.compile()

print(graph.invoke({"text": "start"}))
# {'text': 'start -> A -> B'}
```

**关键认知 1：节点返回的是"更新"而不是完整 state。**
`step_a` 只返回要修改的字段，框架负责合并进全局 State。
默认合并策略是"覆盖"（同名 key 直接替换），更复杂的合并见笔记 02。

**关键认知 2：`invoke` 的输入是 State 的初始值**（只需提供必需字段），
返回值是最终 State（`END` 时刻的完整状态）。

## 4. 节点函数的完整签名

```python
def node(state: State, config: RunnableConfig) -> dict | Command | None:
    ...
```

- `state`：当前全局状态（只读惯例——请返回更新而不是原地修改）
- `config`：运行配置，常用字段：
  - `config["configurable"]["thread_id"]`：会话线程 ID（持久化必需，笔记 07）
  - `config["recursion_limit"]`：超步上限
  - 自定义字段：`config["configurable"]["user_id"]` 等，从 invoke 传入
- 返回 `None` 等价于返回 `{}`（不更新任何状态，但仍会触发下一个超步）

也支持 `@task` 装饰的异步、以及直接把**另一个编译好的图**当节点用（子图，笔记 06）。

## 5. 常用运行方法

| 方法 | 用途 |
|------|------|
| `graph.invoke(input, config)` | 同步阻塞运行，返回最终 state |
| `graph.stream(input, config, stream_mode=...)` | 流式获取过程（笔记 10） |
| `graph.ainvoke(...)` / `astream(...)` | 异步版本 |
| `graph.batch([in1, in2])` | 批量并行运行 |
| `graph.get_state(config)` / `update_state(...)` | 查看/手动修改持久化状态（笔记 07） |

## 6. 什么时候用 LangGraph，什么时候不用

**适合**：
- Agent 需要循环（ReAct、自我修正、评审-修改）
- 多 Agent 编排（Supervisor、流水线、Swarm）
- 需要人工介入/审批/断点续跑的长流程
- RAG 中路由 + 多检索策略 + 重排的组合

**可能过重**：
- 纯线性 prompt 链（直接调 API 就行）
- 一次性无状态问答

## 7. 常见坑

1. **忘了 `add_edge(START, ...)`**：编译报错图无入口。
2. **以为节点收到的是"自己上次返回的 state"**：不是，是全局 State 每次都传最新合并结果。
3. **在节点里原地 `state["x"].append(...)`**：不会报错，但破坏了不可变快照语义，
   时间旅行/并行时会出诡异 bug。永远返回新值。
4. **import 路径**：`START/END` 在 `langgraph.graph`，`Command/Send/interrupt` 在 `langgraph.types`，
   `MemorySaver` 在 `langgraph.checkpoint.memory`。
